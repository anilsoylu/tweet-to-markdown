# Implementation Plans — Tweet to Markdown (Chrome Extension)

Generated by the improve skill on 2026-06-22. Open-source (MIT) Manifest V3
Chrome extension that converts an X (Twitter) thread — a tweet plus the
**author's own self-reply chain** — into a single Markdown document, shown in
an in-page preview panel with one-click copy.

Execute in the order below. Each executor: read the plan fully before starting,
honor its STOP conditions, and update your row when done.

## Product decisions (locked — do not re-litigate)

- **Trigger**: a button injected into the tweet page UI (no popup, no API).
- **Output**: copy-to-clipboard **and** an in-page preview panel.
- **Scope of content**: the original tweet **+ the author's contiguous
  self-reply thread only** (replies from other users are excluded).
- **Media**: embedded as Markdown links — images `![](url)`, videos `[video](permalink)`.
- **No backend, no network calls, no tracking.** Everything runs client-side in
  the content script. This is a hard constraint, stated in the README.

## Technical reality this design is built on

- X has **no free public API**; the only viable approach for a free/OSS tool is
  reading the rendered DOM via a content script while the user is on the tweet
  page. Plans 001/002 assume this.
- The X timeline is **virtualized** — off-screen tweets are unmounted from the
  DOM. Long self-threads must be captured by **scrolling and accumulating** into
  a Map keyed by tweet id (handled in plan 001).
- **DOM selectors are brittle** and will break when X ships UI changes. All
  selectors live in one file (`src/selectors.js`) so a contributor can fix
  breakage in one place. This is an explicit maintenance design goal.

## Findings considered and rejected

- **Use the official X API / a third-party scraping service** — rejected: paid,
  requires keys, and breaks the "free, client-side, no backend" goal.
- **Fetch the tweet from a background service worker by URL** — rejected: X
  returns a JS shell, not server-rendered content; you still need the page open
  and the DOM rendered, so a background fetch buys nothing and adds CORS pain.
- **Bundler/TypeScript build step** — rejected for the MVP: plain classic
  content scripts sharing a `globalThis.TTM` namespace keep the repo
  zero-install and contributor-friendly. Revisit only if the codebase grows.
